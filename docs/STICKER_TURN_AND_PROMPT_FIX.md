# 表情回合预算与当前人格装配修复

## 问题与根因

`StickerPolicy` 是共享服务，旧实现把已发送集合保存在服务实例上。虽然存在 `beginTurn()`，生产 Agent 调用链没有调用它。因此第一张表情成功后，后续回合也会一直被每回合上限拒绝。拒绝结果又统一记为 `onebot-rejected`，不能区分本地策略与网关拒绝。

人格和模拟配置通过受支持接口保存后已被运行时读取；本次并非修复“保存失败”。装配后的可信说明没有明确区分当前管理员配置、消息发送者 Identity、历史助手称呼。新增通用说明，避免将发言者或历史回复误认为当前助手人格。模型的实际表达仍需要真实聊天验收，不能仅凭单元测试保证。

## 修复边界

- Agent 每次同步执行持有可关闭的工具回合 scope，正常结束、取消和异常都会释放；不同线程的回合预算互不清空。
- Sticker 在传输前原子预留预算，避免并发绕过原有全局冷却。确定拒绝释放预留；成功或结果不明消费预算。
- 保留每回合数量限制、冷却、目标会话权限、资产路径/完整性校验、Base64 传输和持久化 Ledger。UNKNOWN 不自动重发。
- 本地 Sticker 拒绝只记录固定白名单原因，不保存任意服务端响应正文。模型工具结果可获得脱敏原因。
- 当前 Persona/Simulation 正文、历史消息及记忆均不改写。Hard Security Policy、工具权限和平台身份边界保持原状。
- 无新增数据库迁移。回合预算仍是运行时保护，不宣称跨重启 exactly-once；重放保护继续由持久化 Ledger 提供。

## 回归覆盖

`StickerTurnLifecycleContractTest` 覆盖连续独立回合、同回合重复、冷却延续与到期、UNKNOWN、异常退出、并发隔离和传输中预留。

`MossReplyReliabilityTest` 新增本地拒绝原因持久化、同一执行键不重复调用及任意错误正文不泄露检查。

`ContextPromptSecurityContractTest` 验证当前人格/模拟各注入一次，消息发送者与助手配置明确区分，历史回复保持非可信上下文，硬安全策略不变。

本说明不包含部署地址、凭据、私人提示词或表情资源。

## 隔离验证结果

Java 全量：458 项，457 通过，0 失败，1 项付费真实 Provider opt-in 跳过。前端 60/60 通过，TypeScript 与生产构建通过。真实 QQ 与生产部署验证另行记录，不把隔离测试等同于生产验收。
